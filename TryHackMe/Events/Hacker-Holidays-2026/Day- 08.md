# Day 8 – Towel on the Sunbed

## Overview

The eighth room of the **TryHackMe Hacker Holidays 2026 CTF** focused on **Web Exploitation** and **Business Logic Vulnerabilities**. The challenge demonstrated how applications can become vulnerable when security relies heavily on business rules and assumptions rather than robust server-side validation.

## Room Details

* **Platform:** TryHackMe
* **Event:** Hacker Holidays 2026
* **Room:** Towel on the Sunbed
* **Category:** Web
* **Difficulty:** Medium

## Scenario

At the Byte Lotus Hotel, a guest rewards application allowed users to claim periodic rewards. The challenge explored how weaknesses in the application's business logic could be abused to gain access to functionality that should normally be restricted.

## Objectives

* Create and explore a guest account.
* Analyze the application's reward mechanism.
* Identify weaknesses in the application's logic.
* Investigate how access restrictions are enforced.
* Complete the challenge objectives.

## Concepts Covered

* Web Exploitation
* Business Logic Vulnerabilities
* API Security
* Request Manipulation
* Server-Side Validation

## What I Learned

* Business logic flaws can exist even when traditional security controls appear to be in place.
* Security decisions should be enforced on the server side rather than relying solely on client-side controls.
* APIs can become a target when application logic is not properly validated.
* Understanding how an application processes requests is essential during security assessments.

## Key Takeaways

* Secure applications require both technical security controls and secure business logic.
* Client-side restrictions should never be trusted as the sole security mechanism.
* Business logic vulnerabilities can lead to unauthorized access without exploiting traditional software bugs.
* Proper validation and authorization checks are critical for protecting application functionality.
